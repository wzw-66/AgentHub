## 新增需求

### 需求：用户注册
系统应允许新用户使用邮箱和密码注册。

#### 场景：注册成功
- **当** 用户提交 `POST /auth/register`，包含有效的 `email`、`name` 和 `password`
- **则** 应创建新用户，返回 `201` 状态码及 `accessToken` 和 `refreshToken`

#### 场景：重复邮箱被拒绝
- **当** 用户使用已存在的邮箱提交注册
- **则** 应返回 `409 Conflict`

### 需求：用户登录
系统应使用邮箱和密码认证用户。

#### 场景：登录成功
- **当** 用户提交 `POST /auth/login`，包含正确的 `email` 和 `password`
- **则** 应返回 `200` 状态码及 `accessToken`（15分钟）和 `refreshToken`（7天）

#### 场景：无效凭据
- **当** 用户提交错误的密码
- **则** 应返回 `401 Unauthorized`

### 需求：令牌刷新
系统应支持刷新过期的访问令牌。

#### 场景：刷新成功
- **当** 用户提交 `POST /auth/refresh`，包含有效的 `refreshToken`
- **则** 应返回新的 `accessToken`

#### 场景：刷新令牌过期
- **当** 用户提交过期的 `refreshToken`
- **则** 应返回 `401 Unauthorized`

### 需求：JWT 认证中间件
受保护的 API 路由需要有效的 JWT 访问令牌。

#### 场景：有效令牌通过中间件
- **当** 请求包含 `Authorization: Bearer <有效的访问令牌>`
- **则** 请求应继续到路由处理器

#### 场景：缺少令牌被拒绝
- **当** 请求没有 `Authorization` 头
- **则** 应返回 `401 Unauthorized`

### 需求：SSE/WS 令牌验证
SSE 和 WebSocket 连接应通过查询参数验证令牌。

#### 场景：SSE 连接使用有效令牌
- **当** 客户端使用 `?token=<有效令牌>` 连接到 SSE
- **则** 连接应建立成功

#### 场景：SSE 连接使用无效令牌
- **当** 客户端使用无效令牌连接到 SSE
- **则** 连接应被拒绝
