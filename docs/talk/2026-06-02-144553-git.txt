● 简单说就是：依赖链决定了谁需要双格式。

  本项目包之间的引用关系：

  shared ──→ db ──→ server  ←── agent-core
    │                      ↑
    └──────────────────────┘

  消费者可能是 CJS，也可能是
  ESM，所以被引用的包（上图左侧）必须同时兼容两者。而链末端的 server
  没人引用它，只作为 node dist/index.js 启动，不存在兼容谁的问题。

  具体说：

  需要双格式的包（库）： 因为有其他包 import 或 require 它们

  ┌──────────────────────┬────────────────────────┬────────────────────────┐
  │          包          │      被哪些包引用      │        引用方式        │
  ├──────────────────────┼────────────────────────┼────────────────────────┤
  │ @agenthub/shared     │ db, server, agent-core │ import（都是 ESM）     │
  ├──────────────────────┼────────────────────────┼────────────────────────┤
  │ @agenthub/db         │ server                 │ import                 │
  ├──────────────────────┼────────────────────────┼────────────────────────┤
  │ @agenthub/agent-core │ server                 │ import                 │
  ├──────────────────────┼────────────────────────┼────────────────────────┤
  │ @agenthub/ui         │ web                    │ import（Next.js 打包） │
  └──────────────────────┴────────────────────────┴────────────────────────┘

  表面上现在全是 import 引用，但作为 npm 包，你不能假设消费者永远用 
  ESM。举个典型场景：如果某个 Electron 主进程脚本用 require("@agenthub/db")
  连接数据库，没有 CJS
  输出就直接报错了。这就是双格式存在的意义——让消费者选择，而不是替消费者选择。

  只需 ESM 的包（应用）： 没有被其他包引用

  ┌──────────────────┬───────────────────────────────┬──────────────────────┐
  │        包        │           被谁消费            │         说明         │
  ├──────────────────┼───────────────────────────────┼──────────────────────┤
  │ @agenthub/server │ 无人引用，直接 node           │ 没人 import 或       │
  │                  │ dist/index.js 运行            │ require 它           │
  ├──────────────────┼───────────────────────────────┼──────────────────────┤
  │ @agenthub/web    │ 浏览器端加载                  │ Next.js 自身处理打包 │
  └──────────────────┴───────────────────────────────┴──────────────────────┘

  所以结论不变：server 移除 CJS 是安全的。但如果将来打算做成
  @agenthub/server-core 让桌面端直接引入 Fastify 实例，那就需要加回双格式。
