● 好的，我已经完整梳理了两个问题的根源。以下是我的分析：

  ---
  问题 1：消息对齐（用户右对齐，Contact 左对齐）

  当前 ChatPanel 的对齐方式实际上使用了两套机制：

  ┌─ div.flex.flex-col (消息容器) ──────────────────┐
  │                                                  │
  │  ┌─ div.message-bubble (textAlign: right) ────┐  │
  │  │  ┌─ div[inline-block, maxWidth:70%] ───┐   │  │
  │  │  │  ┌─ MessageBubble ─────────────────┐ │   │  │
  │  │  │  │  (alignSelf: flex-end)          │ │   │  │
  │  │  │  └─────────────────────────────────┘ │   │  │
  │  │  └──────────────────────────────────────┘   │  │
  │  └─────────────────────────────────────────────┘  │
  └──────────────────────────────────────────────────┘

  当前代码用了 textAlign: "right" 配合 display: 
  inline-block，理论上能工作。但问题是 MessageBubble 内部也用了 alignSelf: 
  flex-end，可惜它外面的父容器是 inline-block（不是 flex 容器），所以内部
  alignSelf 根本没有生效。

  两套对齐互相干扰，导致表现不可靠。

  更好的做法：直接在 flex 容器中使用 alignSelf 或 marginLeft
  来控制每条消息的位置，这比 textAlign 更可靠。

  ---
  问题 2：显示名字（用 name 字段而不是 id）

  用户消息（你发的）：
  - 当前显示：t("chat").you → "YOU" / "你"
  - 你想显示：当前用户的 name 字段
  - 解决方案：useAuth() 提供了 user.username（即服务端返回的 name），用来替代
  "YOU"

  Contact 消息（Agent 回复的）：
  contacts?.find((c) => c.id === msg.senderId)?.name ?? msg.senderId
  - 当 senderId 在 contacts 数组中找不到匹配时，就会 fallback 显示原始
  senderId（看起来像 ID）
  - 关键点：服务端在 messages.ts:441 用 senderId: agent.id
  存储，所以消息记录里有正确的 agent ID
  - 但前端 streaming 时有 senderId: "agent"
  的硬编码（chat-context.tsx:179），这个硬编码 ID 肯定找不到对应的 contact

  SSE 事件名也不匹配——服务端 dispatch agent:xxx:chunk 事件，但前端 useSSEStream
  却在监听 chunk 事件，这说明 streaming 功能可能根本就没正常工作过。

  ---
  你想怎么处理？我的建议是：

  1. 对齐：去掉 textAlign + inline-block 的绕弯做法，直接在外层 div 上用
  alignSelf: variant === "user" ? "flex-end" : 
  "flex-start"（因为外层的父容器就是 flex-col）
  2. 用户名字：从 useAuth() 获取 user.username，替代 user 消息上的 "YOU"
  3. Contact 名字：确保 streaming 消息的 senderId 匹配 contacts 数组中某个
  contact 的 id

  要现在出个改动的方案吗？
