  ---
  群聊工作目录的真相

  当前代码逻辑

  在 executor.ts:142-156 的 resolveWorkspace() 中，工作目录的优先级是：

  1. ✅ Conversation.workspacePath  —— 优先使用
  2. ❌ Agent.workspacePath         —— 仅当对话没有 workspacePath 时才用

  关键问题

  群聊创建时会自动设置 Conversation 级别的工作目录（conversations.ts:106-107）：

  // 路径: agent-workspace/{email}/conversations/{id}/
  const workspacePath =
  `agent-workspace/${safeEmail}/conversations/${conversation.id}`;

  所以无论你在 Agent 上指定了什么工作目录，群聊里所有 Agent
  都跑在对话级别的目录下：

  {WORKSPACE_ROOT}/agent-workspace/{你的邮箱}/conversations/{对话ID}/

  而不是你给 Agent 指定的那个：

  {WORKSPACE_ROOT}/agent-workspace/{你的邮箱}/{Agent名称}/

  为什么单聊没问题？

  单聊的路径在 messages.ts 中直接用的是 agent.workspacePath，只有群聊走的是
  executor.ts 的 resolveWorkspace()，而后者优先取 conversation.workspacePath。

  总结

  ┌──────┬─────────────────────────────────────────────┐
  │ 模式 │               使用的工作目录                │
  ├──────┼─────────────────────────────────────────────┤
  │ 单聊 │ Agent 工作目录 ✅                           │
  ├──────┼─────────────────────────────────────────────┤
  │ 群聊 │ Conversation 工作目录（不是你指定的那个）❌ │
  └──────┴─────────────────────────────────────────────┘

  修复方向

  resolveWorkspace() 应该先尝试使用 Agent 的工作目录，而不是 Conversation
  的。Conversation 的 workspacePath
  作为兜底。或者，更合理的逻辑应该是：如果用户给 Agent
  指定了工作目录，应该优先使用它，Conversation 的目录仅作为无指定时的默认值。
