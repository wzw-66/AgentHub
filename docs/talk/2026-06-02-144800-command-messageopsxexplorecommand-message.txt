  ---
  Bug 分析：AI 回复不保存到数据库

  根因

  在 apps/server/src/routes/messages.ts 的 runAgentExecution() 函数（第 385-439
  行）中，AI 的回复内容从未保存到数据库。

  流程对比：

  用户发消息 → POST /api/.../messages/create
    │
    ├─ 用户消息保存到 DB ✅
    │
    ├─ runAgentExecution() → Claude 适配器执行
    │    ├─ chunk → SSE 推送到前端 ✅
    │    ├─ done → SSE 推送到前端 ✅
    │    └─ ❌ 从未调用 createMessage() 保存 AI 回复到 DB
    │
    └─ 刷新页面 → AI 回复丢失！因为 DB 中没有记录

  对比群聊/编排路径（runOrchestration → ResultAggregator.persist()），它确实通过
   createMessage() 和 createArtifact() 将结果保存到了 DB。

  影响

  ┌────────────────────────┬───────────────────────────────────────┐
  │          场景          │                 结果                  │
  ├────────────────────────┼───────────────────────────────────────┤
  │ SSE 连接活跃时的实时流 │ 正常显示（靠 SSE 事件渲染）           │
  ├────────────────────────┼───────────────────────────────────────┤
  │ 页面刷新后             │ AI 回复消失（DB 中没有 Message 记录） │
  ├────────────────────────┼───────────────────────────────────────┤
  │ SSE 连接中断           │ 回复永久丢失                          │
  └────────────────────────┴───────────────────────────────────────┘

  为什么没有报错

  因为 runAgentExecution 是 fire-and-forget 的异步任务（第 174
  行），即使它不保存 DB，也"不会"报错 — 它只是完成了 SSE 推送就结束了。

  修复方向

  在 runAgentExecution() 中：

  1. 收集 adapter 产出的所有 Text chunk，拼接成完整响应
  2. 完成后调用 createMessage() 保存 AI 回复到 DB，senderType: "Contact",
  senderId: agent.id
  3. 在 "done" SSE 事件中传入真实的 messageId
