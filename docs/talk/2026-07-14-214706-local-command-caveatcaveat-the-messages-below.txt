  ▎
  ▎ 核心考点：这道题实际上在考三个层次的东西：
  ▎
  ▎ 1. 性能测量的严谨性：面试官考你知不知道延迟分布比平均值更重要。P50/P95/P99 
  ▎ 是后端性能分析的基本功。600ms 均值 + 如果你能说出"P99 大概 
  ▎ 1.2s，主要抖动来自于镜像是否被缓存"，那就说明是真的做过 benchmark。
  ▎ 2. Docker exec 的实现原理：docker exec 本质上是调用 Docker API 的 POST 
  ▎ /containers/{id}/exec 创建一个新的进程在容器内运行。每次 exec.start() 
  ▎ 都是一个新的进程，它的工作目录、环境变量、PID 空间都独立于前一次 
  ▎ exec。要做到同一个 agent 多次命令共享同一个工作目录，有三种常见方案：
  ▎   - 方案 A：持久化 shell 会话（如你现在的做法）——在容器内启动一个 /bin/sh 
  ▎ 进程，持续通过 stdin 喂命令。这样 cd 是 shell 内的状态变更。但要注意 shell 
  ▎ 进程退出（比如用户执行了 exit）会干掉整个会话。
  ▎   - 方案 B：每个命令拼接 cd——比如要执行 ls，实际发送的是 cd /project && 
  ▎ ls。缺点：涉及带引号的复杂命令时拼接逻辑很容易碎。
  ▎   - 方案 C：Docker exec 的 -w 参数——每次创建 exec 
  ▎ 时指定工作目录。如你所说，状态不会跨 exec 保持，只能配合方案 B 或 A 使用。
  ▎ 3. 坑的认知：同个 exec 会话内，如果你是用 stdin 
  ▎ 写入命令的方式，标准做法是写入命令字符串然后换行，最后写入 exit 或 EOF
