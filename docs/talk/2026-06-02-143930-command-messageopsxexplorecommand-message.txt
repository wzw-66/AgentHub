  前端 UI 是怎么测的？

  核心理念：不测样式，测行为

  我们不测"按钮是不是蓝色的"（那是浏览器的事），而是测"用户看到什么、点击后发生
  什么"。

  三个关键工具

  vitest         测试运行器（类似但不同于 jest）
    ↓
  jsdom          虚拟浏览器（在 Node.js 里模拟 DOM，不需要打开 Chrome）
    ↓
  @testing-library/react    渲染 React 组件并提供查询工具

  具体怎么跑？

  执行 pnpm --filter @agenthub/ui test 后：

  1. vitest 启动
  2. jsdom 在内存中创建一个 "假浏览器"（没有界面）
  3. 找到所有 *.test.tsx 文件
  4. 对每个测试：
     a. render(<组件 />)  → 把组件渲染到假浏览器里
     b. screen.getByTestId("xxx")  → 在假 DOM 中找元素
     c. expect(...).toBeInTheDocument()  → 验证元素存在
  5. cleanup() → 清空假浏览器，准备下一个测试
  6. 输出结果：6 passed, 29 passed ✓

  拿 AgentAvatar 举例

  看这个实际组件和它的测试：

  组件代码：

  // 有图片时
  if (avatarUrl) {
    return <img src={url} data-testid="agent-avatar-img" />;
  }

  // 没图片时
  return <div data-testid="agent-avatar-initials">C</div>;

  关键点：组件里写了 data-testid="agent-avatar-img"——这是一个"测试身份证"，测试
  通过这个来找元素，不依赖 CSS 类名或 DOM 结构。

  测试代码：

  it("renders image when avatarUrl is provided", () => {
    // ① 渲染组件，传入参数
    render(<AgentAvatar name="Test Agent" 
  avatarUrl="https://example.com/avatar.png" />);

    // ② 通过 data-testid 找到图片元素
    const img = screen.getByTestId("agent-avatar-img");

    expect(img).toHaveAttribute("alt", "Test Agent");

  再拿 CodeBlock 的复制功能举例

  it("calls clipboard API on copy button click", async () => {
    // ① 模拟剪贴板 API（假功能，不会真复制）
    const writeText = vi.fn().mockResolvedValue(undefined);

  测试策略总结

  ┌────────────────────────────────────────┬──────────────────────────┐
  │               你写的代码               │       测试验证什么       │
  ├────────────────────────────────────────┼──────────────────────────┤
  │ <img src={url} />                      │ 图片存在、src 正确       │
  ├────────────────────────────────────────┼──────────────────────────┤
  │ {status === "building" && <Spinner />} │ building 时 Spinner 存在 │
  ├────────────────────────────────────────┼──────────────────────────┤
  │ navigator.clipboard.writeText()        │ writeText 被调用         │
  ├────────────────────────────────────────┼──────────────────────────┤
  │ className={className}                  │ className 透传了         │
  ├────────────────────────────────────────┼──────────────────────────┤
  │ 时间戳格式化                           │ 显示 "18:30" 格式        │
  └────────────────────────────────────────┴──────────────────────────┘

  用数据库测试做类比

  如果你用过后端测试：

  后端测试：连接测试数据库 → 插入数据 → 调用接口 → 验证返回值
  前端测试：jsdom虚拟浏览器 → 渲染组件 → 查找元素 → 验证元素状态

  本质是一样的：安排（Arrange）→ 执行（Act）→ 断言（Assert）。只是前端操作的是
  DOM 元素而非数据库记录。

❯ 你的意思是只检查ts逻辑代码，不检查css样式？                                   

● 对，本质上是这样。让我说得更直白一点。

  我们能测什么（TS 逻辑）

  // ✅ 条件渲染
  if (avatarUrl) {
    return <img />  // 测：有 url → img 出现
  } else {
    return <div>C</div>  // 测：无 url → 首字母出现
  }

  // ✅ 点击事件
  fireEvent.click(button)
  expect(writeText).toHaveBeenCalled() // 测：点击→调用了剪贴板

  // ✅ 数据转换
  formatTime("2026-05-27T10:30:00Z") → "18:30" // 测：ISO 转成 HH:mm

  // ✅ className 透传
  <Component className="custom" />
  expect(el.className).toContain("custom") // 测：外面传的 class 接住了

  我们测不了什么（纯 CSS）

  /* ❌ 颜色 */
  --ui-color-bg-user: #3b82f6;

  /* ❌ 字体大小 */
  font-size: 15px;

  /* ❌ 圆角 */
  border-radius: 8px;

  /* ❌ 对齐方式 */
  align-items: flex-end;

  这些 jsdom 根本不管。jsdom 是一个"假浏览器"，它知道你写了一个 style 或者
  className，但它不会去计算这个元素的最终视觉效果。

  一个例子让你感受

  就算我在组件里写了：

  <div style={{ color: "red", fontSize: "100px" }}>Hello</div>

  测试照样能通过：

  expect(el).toHaveTextContent("Hello");  // ✅ 通过
  expect(el).toHaveStyle({ color: "red" }); // 有些也能通过（因为 style 属性在 
  DOM 上）

  但如果我写成 CSS 文件：

  .text { color: red; }

  测试就完全不知道了，因为 jsdom 不加载 CSS 文件。

  那 CSS 怎么保证？

  ┌───────────────────────┬──────────────────────────────┐
  │         方式          │            谁负责            │
  ├───────────────────────┼──────────────────────────────┤
  │ 测试                  │ 行为逻辑、条件渲染、事件处理 │
  ├───────────────────────┼──────────────────────────────┤
  │ 开发时肉眼确认        │ 你打开浏览器看               │
  ├───────────────────────┼──────────────────────────────┤
  │ Storybook（未来可加） │ 组件独立预览，截图对比       │
  ├───────────────────────┼──────────────────────────────┤
  │ E2E 测试（未来可加）  │ Playwright 打开真浏览器截图  │
  └───────────────────────┴──────────────────────────────┘

  一句话总结

  测试保证的是**"功能对不对"（点了按钮是不是复制了、有图片是不是显示了），不保证
  "好不好看"**（颜色正不正、间距对不对）。好不好看还是得用眼睛看。
