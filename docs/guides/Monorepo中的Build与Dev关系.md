# Monorepo 中的 Build 与 Dev 关系详解

在 AgentHub 项目中，`build` 和 `dev` 脚本不仅是简单的编译和运行，它们在 Turborepo 的管理下存在着严密的逻辑依赖关系。

## 1. 核心依赖机制

项目根目录的 [turbo.json](file:///d:/code/github/AgentHub/turbo.json) 定义了任务间的拓扑关系：

```json
"dev": {
  "dependsOn": ["^build"],
  "persistent": true
}
```

- **`^build` 的含义**：在启动任何一个包（如 `apps/web`）的开发服务器（`dev`）之前，Turborepo 会确保其依赖的所有“上游包”（如 `packages/shared`）已经完成了构建（`build`）。
- **为什么要这么做？**：Monorepo 中的包通过 `workspace:*` 互相引用。引用方通常需要读取被引用包 `dist/` 目录下的编译产物和类型定义文件（.d.ts）。如果从未构建过，就会出现“找不到模块”的错误。

## 2. 任务对比：Build vs Dev

| 特性         | Build (构建)                    | Dev (开发)                       |
| :----------- | :------------------------------ | :------------------------------- |
| **主要目标** | 生成生产环境可用的静态产物      | 提供实时反馈的开发环境           |
| **执行频率** | 部署前或重大配置变更后运行一次  | 日常开发时持续运行               |
| **输出产物** | 压缩、优化后的 JS/CSS、静态页面 | 内存中的热更新数据、本地服务端口 |
| **缓存机制** | 强依赖缓存，代码未变则秒速跳过  | 监听文件变动，自动触发增量编译   |

## 3. 日常开发工作流

### 情况 A：修改业务代码

如果你只修改 `apps/server` 或 `apps/web` 内部的逻辑：

- **操作**：保持 `pnpm dev` 运行即可。
- **效果**：`tsx watch` (后端) 或 Next.js HMR (前端) 会实时捕捉变动并重启，**无需运行 build**。

### 情况 B：修改共享包代码

如果你修改了 `packages/db` 或 `packages/shared`：

- **操作**：同样只需运行顶层的 `pnpm dev`。
- **效果**：Turborepo 会自动检测到共享包的变动，先触发共享包的构建，再让依赖它们的后端/前端服务感知到更新并重启。

## 4. 什么时候必须手动 Build？

1. **新环境初始化**：拉取代码后，首次生成所有包的类型定义，消除 IDE 红线。
2. **生产环境部署**：生成优化后的最终包。
3. **重大配置变更**：修改了 `tsconfig.json`、`turbo.json` 或 `package.json` 的导出字段后，建议清理缓存并重新 build。

## 总结

在 AgentHub 中，**`dev` 是基于 `build` 产物的实时运行模式**。得益于 Turborepo 的自动化调度，你通常只需要运行 `pnpm dev`，系统就会自动处理好所有的构建先后顺序，让你专注于代码编写。
