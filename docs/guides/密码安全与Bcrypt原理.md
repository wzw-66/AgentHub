# 密码安全：Bcrypt 哈希与验证原理详解

在本项目中，密码的安全存储与验证是由 [password.ts](file:///d:/code/github/AgentHub/apps/server/src/utils/password.ts) 负责的。它利用了 `bcrypt` 算法来确保即便数据库泄露，用户的原始密码也不会被轻易破解。

## 1. 为什么不能直接存密码？

如果直接存储明文密码，一旦数据库被黑客窃取，所有用户的账户将瞬间失守。即使是简单的 MD5 或 SHA256 哈希，也容易受到“彩虹表”（预计算的哈希字典）的攻击。

## 2. Bcrypt 的核心机制：盐 (Salt) 与 迭代

### 什么是“盐”？

“盐”是一个随机生成的字符串。在加密时，它会被混合进原始密码中。

- **作用**：确保即使两个用户的原始密码相同（例如都是 `123456`），他们存储在数据库中的哈希值也完全不同。
- **位置**：Bcrypt 会将随机生成的盐直接编码在最终的哈希字符串中。

### 什么是迭代 (Cost Factor)？

在 [password.ts](file:///d:/code/github/AgentHub/apps/server/src/utils/password.ts) 中，`SALT_ROUNDS = 10` 表示算法会执行 $2^{10} = 1024$ 次哈希运算。

- **作用**：人为地增加计算时间。这不会影响正常用户登录（只需几百毫秒），但会让黑客暴力破解的速度下降数千倍。

---

## 3. 密文结构解析

一个典型的 Bcrypt 密文如下：
`$2b$10$N9qo8uLOickgx2ZMRZoMyeIjZAgcfl7p92ldGxad68LJZdL17lhWy`

| 部分         | 内容     | 含义                           |
| :----------- | :------- | :----------------------------- |
| **$2b$**     | 算法版本 | 标识使用的是 Bcrypt 的哪个版本 |
| **$10$**     | 成本因子 | 迭代次数，这里是 $2^{10}$ 次   |
| **前 22 位** | 随机盐   | 加密时随机生成的干扰项         |
| **剩余位**   | 哈希摘要 | 真正的密码密文部分             |

---

## 4. 验证流程：为什么“随机盐”也能比对成功？

当你调用 `comparePassword(plain, hash)` 时，内部逻辑如下：

1. **提取信息**：函数从数据库存的 `hash` 字符串中，直接提取出当初加密时用的 **算法版本**、**成本因子** 和 **随机盐**。
2. **重新哈希**：使用提取出的“盐”和“成本因子”，对用户当前输入的“明文密码”重新运行一次哈希运算。
3. **安全对撞**：将新计算出的结果与数据库中的结果进行比对。如果完全一致，则密码正确。

## 5. 常见疑问解答

### Q：盐都写在密文里了，黑客不也能看到吗？

**A**：是的，黑客能看到。但盐的目的不是“保密”，而是“**去通用化**”。

- 因为每个人的盐都不同，黑客无法使用预先准备好的“彩虹表”进行批量破解。
- 他必须针对你数据库里的每一个用户，单独花费巨大的算力去暴力尝试，这极大地增加了破解成本。

### Q：黑客也能看到盐和迭代次数，这不还是不安全吗？

**A**：这是一个常见的误区。密码学的基本原则是：**安全性应依赖于数学难度，而非算法的保密性**。

1. **计算成本的碾压**：即使黑客知道所有参数，他依然需要“猜”密码。普通 MD5 一秒能猜 10 亿次，而 Bcrypt（10轮）一秒只能猜约 1000 次。对于一个复杂的 8 位密码，破解 MD5 可能只需 2 天，而破解 Bcrypt 可能需要 **6000 年**。
2. **无法“批发”破解**：由于随机盐的存在，黑客无法通过一次计算破解多个相同密码的用户。他必须为每个用户单独投入几千年的算力。
3. **自适应性**：随着硬件变快，我们只需将迭代轮数（Cost Factor）增加 1，黑客的破解成本就会**翻倍**，而正常用户几乎感知不到延迟。

### Q：如果把盐塞在密码中间，不是更安全吗？

**A**：这属于“隐蔽实现安全”，在专业领域并不推荐。
- **规则易泄露**：一旦代码或规则泄露，这种“塞在中间”的逻辑对黑客来说计算难度完全没变。
- **雪崩效应**：现代哈希函数只要输入改变 1 位，输出就会翻天覆地。无论盐在开头、中间还是末尾，其混乱程度是同级的。
- **更强的方案：Pepper（胡椒粉）**：如果你想更安全，可以使用 Pepper。Salt 存数据库，Pepper 存环境变量（不进数据库）。这样黑客即便偷走数据库，只要拿不到 Pepper，也完全无法开始破解。

## 总结

通过 `bcrypt`，我们实现了：

1. **单向不可逆**：无法从密文反推明文。
2. **抗彩虹表**：每个用户拥有唯一的随机盐。
3. **抗暴力破解**：通过迭代次数拉高黑客的时间成本。
