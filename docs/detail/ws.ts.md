这个文件 [ws.ts](file:///d:/code/github/AgentHub/apps/server/src/routes/ws.ts) 是后端处理 **WebSocket（长连接）** 的核心逻辑。它让应用能够实现“实时”功能，比如：谁正在输入、谁上线了、消息即时送达等。

我们可以按照功能模块来拆解这些函数的作用：

### 1. `wsHandlers` (消息处理器地图) (L16-L44)

这不是一个单一函数，而是一组“处理器”。当服务器收到客户端发来的消息时，会根据消息类型在这里找对应的处理逻辑：

- **`typing:start` / `typing:end`**：当你在聊天框打字时，它会通过 `broadcastToConversation` 告诉房间里的其他人：“XXX 正在输入...”。
- **`message:read`**：处理已读回执（目前代码中仅作为预留）。
- **`ping`**：心跳回应。客户端发个 `ping`，服务器回个 `pong`，确保连接还没断。

### 2. `broadcastStatus` (状态广播助手) (L48-L58)

- **作用**：这是一个辅助函数，专门用来向全网广播某个用户的**在线/离线**状态。
- **触发时机**：当用户刚连上 WebSocket 时播报 "online"，当用户断开连接时播报 "offline"。

### 3. `handleWSConnection` (连接总管) (L62-L122)

这是整个文件**最核心**的函数。每当有一个新用户尝试建立 WebSocket 连接时，它会执行以下流程：

- **身份验证 (L65-L75)**：
  - 从 URL 的参数中提取 `token`。
  - 调用 `verifyQueryToken` 校验身份。如果校验失败，直接关闭连接并返回错误码 `4001`。
- **注册连接 (L79-L82)**：
  - 将该用户的 Socket 实例存入 `ConnectionManager` (cm)，方便后续定向推送消息。
  - 广播该用户已上线。
- **心跳监测 (L86-L94)**：
  - 设置一个 60 秒的定时器。如果 60 秒内没收到任何消息，服务器会认为该用户掉线了，主动关闭连接（错误码 `4002`）。
- **消息监听 (L98-L109)**：
  - 监听客户端发来的原始数据。
  - 解析 JSON，并根据消息类型在 `wsHandlers` 中匹配对应的处理器执行。
- **断开处理 (L113-L117)**：
  - 当用户主动关闭网页或网络断开时，清理定时器，从管理器中移除该连接，并广播其已下线。

### 4. `wsRoutes` (插件入口) (L126-L128)

- **作用**：这是一个 Fastify 插件。
- **功能**：它将 `/ws` 这个路径注册到服务器上，并开启 WebSocket 模式，指定由 `handleWSConnection` 来处理所有连到这个路径的请求。

---

### 总结

- **`wsRoutes`**：开启大门（注册路径）。
- **`handleWSConnection`**：接待客人（验证、登记、陪聊、送客）。
- **`wsHandlers`**：聊天话题分类（处理具体业务指令）。
- **`broadcastStatus`**：广播喇叭（通报上下线）。

这个文件配合前端，共同实现了 AgentHub 丝滑的实时交互体验。
