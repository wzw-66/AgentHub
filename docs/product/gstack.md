根据 gstack 使用指南，以下是被强调为**核心、高频使用或覆盖关键开发阶段**的重要技能（按开发流程排序）：

---

### 1. `/office-hours` — 需求澄清与设计发起

- **角色**：合伙人
- **作用**：通过6个追问重新定义问题、挑战前提，生成结构化的设计文档（问题定义、用户画像、方案对比、推荐路径）。
- **重要性**：所有新功能的起点，避免“做错方向”。

### 2. `/plan-eng-review` — 技术方案评审

- **角色**：技术主管
- **作用**：审查架构漏洞、故障模式、测试覆盖度，识别关键风险（如文档中列举的 Critical 风险）。
- **重要性**：发布前的必过关卡，确保工程质量。

### 3. `/autoplan` — 自动化全流程评审

- **作用**：一键依次运行 CEO、设计、工程、DX 评审，产出详尽的评审报告（含架构图、故障注册表、测试计划等）。
- **重要性**：高效生成多维度评审意见，避免遗漏。

### 4. `/review` — 代码审查与自动修复

- **角色**：Staff Engineer
- **作用**：检查当前代码差异，自动修复低级问题（缺少异常处理、硬编码密钥等），不确定处询问用户。
- **重要性**：每日开发使用，提升代码质量，减少人工 review 负担。

### 5. `/qa` — 自动化端到端测试

- **角色**：QA 工程师
- **作用**：启动浏览器执行完整测试（点击、填表单、检查报错、性能指标），发现 bug 直接修复，并为每个 bug 生成回归测试。
- **重要性**：保障功能正确性和 UI 稳定性，输出健康评分。

### 6. `/investigate` — Bug 根因调查

- **作用**：排查 bug 时先找出根本原因再修复，避免重复踩坑，锁定修改范围防止误改。
- **重要性**：系统化的调试方法，适合复杂问题定位。

### 7. `/ship` — 一键发布

- **角色**：发布工程师
- **作用**：自动同步分支 → 运行测试 → 更新版本号和 CHANGELOG → 创建 commit → 推送并创建 PR。
- **重要性**：单人/小团队最常用的发布入口。

### 8. `/land-and-deploy` — 合并与部署（团队模式）

- **作用**：等待 PR 审查和 CI 通过后，合并代码 → 部署到生产环境 → 自动健康检查。
- **重要性**：配合 `/ship` 完成 CI/CD 闭环。

### 9. `/canary` — 生产环境金丝雀监控

- **角色**：SRE
- **作用**：部署后持续轮询生产环境，检查页面状态、控制台错误、核心性能指标（LCP/CLS），记录异常并生成健康评分。
- **重要性**：部署后的安全网，帮助快速发现问题或确认稳定。

---

**总结**：以上9个技能覆盖了 **需求→评审→编码→测试→发布→监控** 的主链路，是 gstack 最核心、日常开发中最有价值的功能。其余如 `/design-review`、`/scrape`、`/devex-review` 等为辅助或特定场景技能。
