**旁白：**

**画面动效：**

**旁白：**

**画面动效：**
8. 回到左侧，展示对话列表的「置顶」「归档」「搜索」操作。

**旁白：**
> 左侧的对话列表可以同时管理多个会话——不同的任务放在不同的对话窗口，消息互不干扰、上下文独立。每个对话保持完整的聊天历史，随时可以切换回来继续上一次的工作。

> 而当你的需求复杂到一个人搞不定的时候——群聊模式登场了。

### 01:00 - 01:40 场景二：多 Agent 编排与群聊

**画面：** 进入群聊界面，顶部显示群成员头像列表（Claude、Codex、Custom Agent）。

**旁白：**
> 在群聊中，一个对话里包含多个 Agent，每个 Agent 都是独立的"群成员"——有自己的角色定位和擅长领域。你可以像拉群一样组织它们，也可以直接在群里 @ 指定某个 Agent 来处理特定任务。

**画面动效：**
1. 输入框发送："帮我写一个个人博客网站，包含首页、文章列表和关于页面" → 发送。
2. 画面上方出现 **Orchestrator 协调中** 的标识，显示一个动态的 DAG 任务分解图动画（绿色节点表示正在执行，灰色表示待执行）——这是一个关键视觉亮点。
3. 节点依次变绿：意图分析 → 任务分解 → Claude 写首页 → Codex 写文章列表 → 自定义 Agent 写关于页 → 结果聚合。

**旁白：**
> 这里就是 AgentHub 最核心的技术亮点——Orchestrator 编排引擎。你发送需求后，Orchestrator 会通过 LLM 自动进行意图分析，将复杂任务拆解为若干子任务，并分析它们之间的依赖关系，构建出一个有向无环图——也就是 DAG。

> 然后，它按照这个 DAG 进行智能调度：没有依赖的任务并行执行，有依赖的按序等待。比如这里，Claude 写首页、Codex 写文章列表、自定义 Agent 写关于页——三个互不依赖的任务同时开工。每一步的进度都在聊天流中实时可见，你不需要猜测 Agent 在做什么。

**画面动效：**
4. 三个 Agent 的回复以**分栏/分块**的方式依次出现在聊天流中（每个回复带 Agent 头像和名称标签），代码块中展示各自的产出。
5. 最后出现一条聚合后的汇总消息："已完成三个页面的开发..."

**旁白：**
> 每个 Agent 的产出以独立的卡片展现在聊天流中——带着各自的头像、名称标签、代码块，清晰可辨。所有任务完成后，Orchestrator 自动聚合结果，生成一份汇总交付给你。

> 更健壮的是——如果下游任务依赖上游结果，调度器会耐心等待；如果某个 Agent 执行失败，系统自动跳过或降级处理，不会让整个流程卡死。这在实际的多 Agent 协作中至关重要。

**画面动效（亮点——交互模式）：**
6. 在某个 Agent 执行过程中 → 弹出交互卡片（"我想确认一下：博客的主色调偏好是什么？"）→ 选项按钮 + 输入框 → 用户选择/输入 → 回复 → Agent 继续执行。

**旁白：**
> 但最有意思的是这个——Agent 在执行过程中遇到不确定的决策点时，它不是擅自猜测，也不是卡住不动，而是主动向你提问。

> 比如 Agent 弹出交互卡片："博客的主色调偏好是什么？"——你选择一个选项或直接输入回答，Agent 收到你的反馈后继续执行。这不是单向的指令下发，而是人与 AI 之间真正的双向对话。Agent 不再是黑盒子，它是一个可以沟通的协作者。

### 01:40 - 02:10 场景三：Agent 生态

**画面：** 切换到 `/agents` 页面（Agent 列表页）。

**旁白：**
> 聊完了核心体验，我们来看看 AgentHub 的另一面——Agent 生态。它不止是接入几个现成的 AI 平台，更是一个开放的、可生长的 Agent 生态体系。

**画面动效：**
1. 展示 Agent 列表：Claude Code、Codex、OpenCode 等（带 Provider 标签、能力标签、模型名）。
2. 点击「自建 Agent」按钮 → 弹出创建表单 → 填写名称、System Prompt、选择 Provider（Claude/Codex/Custom）、配置模型和 API 端点 → 点击创建。

**旁白：**
> 平台内置了 Claude Code、Codex、OpenCode 这三大主流 Agent 适配器——底层通过统一的适配器层屏蔽了各个平台的 API 差异。对于开发者来说，接入一个新的 Agent 平台只需要实现一个接口。

> 更酷的是，你可以在对话式界面中自建 Agent。不需要写代码——设定它的名字、System Prompt、选择底层 Provider 和模型，几秒钟就能创建出一个专属的 AI 助手。你可以赋予它特定的角色定位、知识边界、工具权限——它就是为你团队定制的数字化成员。

**画面动效：**
3. 切换到 `/market` 页面 → 展示 Agent 市场，有搜索框、Provider 筛选器、卡片网格。
4. 点击一个 Agent 卡片 → 进入详情页（展示头像、描述、统计、System Prompt）。
5. 点击「导入」→ 该 Agent 出现在联系人列表中。

**旁白：**
> 自建的 Agent 还可以一键发布到 Agent 市场。市场中有搜索和筛选功能，你可以浏览其他人发布的 Agent，查看他们的 System Prompt、能力标签和统计数据。看到中意的，点击导入，它就出现在你的联系人列表中了。

> Agent 像 APP 一样可发现、可安装、可复用——这不仅仅是工具，这是一个正在生长的 AI 生态。

**画面动效：**
6. 切换到 `/credentials` 页面 → 展示已配置的 API Key 列表（密钥掩码显示），点击「新建」→ 输入名称、Provider、Key → 保存。

**旁白：**
> 统一凭证管理界面让 API Key 安全存储，密钥在列表中自动掩码，既安全又方便。对于自建的 Custom Agent，只需要配置一个 API 端点和模型名称，就可以接入任何兼容 OpenAI 格式的服务——你的私有 Agent 也能参与群聊协作。

### 02:10 - 02:45 场景四：产物预览与编辑

**画面：** 回到群聊对话，Agent 回复中出现了产物卡片。

**旁白：**
> Agent 的产出不只是文字。如果你观察过日常的 AI 对话，你会发现大部分时候 AI 给你的只是代码块或文字描述，但你看不到实际效果。AgentHub 改变了这一点——产物内联预览是我们体验上的核心亮点。

**画面动效：**
1. 聊天流中展示一个 HTML 产物卡片（显示页面缩略图 + 文件名 + 类型标签）。
2. 点击卡片 → 平滑展开全屏预览（ArtifactPreviewModal），页面在 iframe 中渲染可交互的网页。
3. 关闭预览。

**旁白：**
> Agent 生成 HTML 页面后，聊天流中直接出现一个网页预览卡片——显示页面缩略图、文件名、类型标签。点击卡片，平滑展开成全屏预览，页面在 iframe 中是可交互的，你可以点击按钮、查看样式、测试功能。不用离开聊天界面，你就能看到 Agent 产出的真实效果。

**画面动效：**
4. 展示另一个带有 Diff 视图的消息：绿底显示新增代码，红底显示删除代码，逐行对比。

**旁白：**
> 代码修改以 Diff 视图展示——绿色代表新增，红色代表删除，逐行对比。在 Agent 根据你的反馈迭代修改时，你能清晰地看到每一步的变化，而不是每次都重新看一遍完整代码。这不仅提升了协作效率，也让审查变得更加可靠。

**画面动效：**
5. 右侧面板切换到「文件」Tab → 展示项目的文件树（FileExplorer）→ 点击展开目录 → 点击文件在 FileEditor 中预览代码。
6. 切换到「预览」Tab → 再次展示 iframe 预览。

**旁白：**
> 右侧面板集成了完整的文件工作区。Agent 为每次对话创建一个独立的项目目录，文件树清晰展示所有产出文件——你可以展开目录、点击文件、在代码编辑器中预览和修改。对于 HTML 和 SVG 文件还提供了预览和代码分栏切换。

> 整个项目的工作区一目了然——Agent 生成了什么、文件结构是怎样的、代码能不能跑——全部在同一个界面内可见。

**画面动效：**
7. 演示文件附件功能：点击输入框的附件图标 → 选择一张图片 → 图片以缩略图嵌入输入框 → 发送 → Agent 基于图片内容回复。

**旁白：**
> 消息输入框支持文件附件——点击附件图标选择一张图片或文档，它会以缩略图形式嵌入输入框。发送后，Agent 能理解附件的内容并基于它进行回复。就像给同事发文件一样自然，Agent 不需要你长篇描述——给它看图，它就能看懂。

### 03:00 - 03:10 收尾：技术架构

**画面：** 画面切换为技术架构图（快速展示）：

```
User → Next.js UI → Fastify API → Orchestrator (DAG)
                                         ↓
                          ClaudeAdapter  CodexAdapter  CustomAdapter
                                         ↓
                              AgentHarness (Tool Use)
                                         ↓
                              File System / Sandbox
```

**旁白：**
> 最后看一下技术架构。前端是 Next.js 14 + Tailwind CSS，后端是 Fastify + Prisma + PostgreSQL，中间是核心的 Agent 适配器层和 DAG 编排引擎。全栈 TypeScript，严格的类型安全，清晰的模块化分层。

> 每个 Agent 的接入都通过统一的 AgentAdapter 接口屏蔽底层差异。编排引擎采用 LLM 驱动意图分解 + DAG 并行调度 + 自动降级容错。实时通信层同时支持 SSE 流式输出和 WebSocket 双向消息。

> 整个项目 19000+ 行核心代码，从架构设计到代码实现，全部通过与 AI 协作完成——正如 AgentHub 所倡导的：**与 AI 协作，释放创造力。**
