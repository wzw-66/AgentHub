Superpowers 是一套为 AI 编程助手（如 Claude Code, Cursor 等）设计的开源技能库，就像一个标准化的“工作流操作系统”，通过一系列结构化的技能模块，引导 AI 遵循从需求分析到部署的完整工程化流程，旨在将 AI 的编码行为从“直觉驱动”转变为“流程驱动”，从而提升代码质量和协作效率。

它的核心原则是 **“流程优于提示”（Process over Prompt）** ，其所有技能主要分为以下几类：

| 技能分类          | 核心技能                         | 功能说明                                                                                                                    |
| :---------------- | :------------------------------- | :-------------------------------------------------------------------------------------------------------------------------- |
| **🤔 思考与规划** | `brainstorming`                  | 启动项目前，通过深入提问来澄清需求、探索方案，并生成设计文档，有效避免需求理解偏差。                                        |
|                   | `writing-plans`                  | 将批准的设计方案拆解为一份包含具体步骤、文件路径和验证条件的详细任务清单，将复杂需求转化为可执行的“小任务”。                |
| **⚙️ 开发与执行** | `test-driven-development` (TDD)  | 强制执行“红-绿-重构”的TDD循环：在编写任何功能代码前，必须先编写一个会失败的测试，确保代码的可测试性和正确性。               |
|                   | `subagent-driven-development`    | 为一个计划中的多个独立任务分别派遣全新的、上下文隔离的子代理来并行执行，并能进行两阶段审查，显著提升开发效率。              |
|                   | `executing-plans`                | 按照 `writing-plans` 生成的计划，分步骤、带检查点地执行任务，每完成一步都会暂停等待确认，避免AI一次性输出大量代码导致失控。 |
| **🐞 调试与质量** | `systematic-debugging`           | 提供结构化的调试方法，要求AI先构建故障假设并收集证据，再提出修复方案，杜绝“猜谜式”调试，有效定位根本原因。                  |
|                   | `verification-before-completion` | 在AI声称任务完成前，强制其运行验证命令并提供实际输出作为成功证据，防止AI“幻觉式”地宣称成功。                                |
|                   | `requesting-code-review`         | 在合并代码或任务间隙，对代码进行多维度（功能、质量、安全、性能）的审查，并按严重程度报告问题，严重问题会阻碍进度。          |
| **🤝 协作与集成** | `using-git-worktrees`            | 熟练运用Git Worktrees创建独立的开发分支工作区，实现环境隔离，确保主分支的稳定。                                             |
|                   | `finishing-a-development-branch` | 当开发任务完成后，进行最终验证，并提供合并、创建PR、保留或丢弃分支等选项，规范化分支收尾流程。                              |
|                   | `dispatching-parallel-agents`    | 当遇到两个以上可并行的独立任务时，一次性派发多个AI代理同时处理，最大化并行效率。                                            |
| **🧠 元能力**     | `writing-skills`                 | 这是一个“元技能”，指导用户如何按照Superpowers的规范和测试方法论，创建或修改新的技能，实现无限扩展。                         |

这些技能通常会被组合成一个完整的工作流，覆盖从0到1的开发全过程：

1. **需求 → 设计**：`using-superpowers` 入口，`brainstorming` 输出设计文档。
2. **设计 → 计划**：`writing-plans` 将设计拆解为任务清单。
3. **计划 → 编码**：`subagent-driven-development` 或 `executing-plans` 开始执行。
4. **编码阶段**：`test-driven-development` 保证每个功能的正确性。
5. **任务间隙**：`requesting-code-review` 确保代码质量。
6. **开发完成**：`verification-before-completion` 做最终验证，`finishing-a-development-branch` 完成分支收尾。

实际测试表明，使用Superpowers的项目，平均成本约降低9%，测试覆盖率可从约60%提升至约90%。不过，它更加适合有一定复杂度、需要长期维护的项目，对于小型快速原型或个人Demo可能会显得流程过于繁琐。
