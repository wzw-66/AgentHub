## 一、产品概述

### 一句话描述
AgentHub 是一个**以IM聊天为核心交互范式的多Agent协作平台**，让开发者像建群聊天一样组建自己的AI团队。

### 核心叙事
> **"我们不是在做一个Agent平台，我们是在造一个会聊天的同事。"**

### 解决的问题
现有AI Agent工具（Claude Code、Cursor、Codex等）以独立形式存在，用户需在多个工具间反复切换、粘贴上下文、手动协调。没有一个统一的入口让用户像聊天一样与多个Agent协作完成复杂任务。

## 三、核心功能清单

### P0 — 基础体验（必须做）
- IM聊天UI（对话列表、消息流、输入框），白底简洁风格，飞书式蓝色体系
- SSE流式消息（打字机效果）+ 指数退避重连
- 1个真实Agent集成（LLM API），API Key管理
- 产物内联卡片：代码块、Diff、网页预览、部署状态
- 右侧实时预览面板（「预览」「辩论」「分支」「版本」四个Tab）
- 微信式折叠群成员管理（头像堆叠→点击展开→hover踢人）

### P0 — 创新功能（必须做）
- **Agent Debate（辩论）** — 两个Agent同时"正在输入"，一个提方案，另一个反驳，第三个汇总。点击"播放辩论"按钮逐条展示
- **🎧 静默审查者（Silent Reviewer）** — 安全审查Agent全程静默，发现安全问题时突然弹出告警
- **🤔 Agent犹豫（Hesitation）** — Agent在不确定时主动表达风险并提供选项让用户决策
- **⏳ 对话即版本（Chat as Version Control）** — 版本时间轴展示每次代码变更，可回滚

### P1 — 扩展功能（选做）
- 截图→代码（拖图上传→Vision API→生成HTML）
- /pr 对话即PR（输入/pr → Agent整理变更→输出PR描述）
- 对话分支（任意消息点击"分支"创建新对话）

### P2 — 产品文档中有设计但不实现
- 移动端适配
- 部署发布流水线
- 点赞反馈影响Agent行为
- 对话快照分享链接

## 四、8个让人眼前一亮的设计亮点

### 1. 截图→代码
拖一张Figma设计稿截图到聊天框，Agent分析图片直接生成HTML/CSS。
**评审反应：** "它能看懂图？"

### 2. Agent 辩论 🆚
两个Agent同时"正在输入"，提方案→反驳→回应→汇总。评审看到两个AI在讨论方案优劣。
**评审反应：** "两个AI在吵架？"

### 3. 🎧 静默审查者
Security Agent全程不发言，发现XSS漏洞时突然弹出红色告警。
**评审反应：** "它一直听着但没说话，直到发现问题才开口？"

### 4. 🤔 Agent 犹豫
Agent不直接说"好的我做"，而是分析风险→给出选项→让用户决策。
**评审反应：** "AI会说自己不确定？"

### 5. ⏳ 对话即版本
拖拽时间轴滑块或点击版本列表，聊天和代码一起回滚到历史节点。
**评审反应：** "聊天也能做版本控制？"

### 6. 多Agent"正在输入"动画
2-3个头像同时跳动"正在输入..."然后先后回复。
**评审反应：** "它们在并行工作？"

### 7. 对话分支时间轴（Canvas）
右侧面板的Canvas绘制分支树，显示对话分叉路径。
**评审反应：** "这个有点Git的感觉。"

### 8. 辩论对比表
Orchestrator总结辩论时输出方案A vs 方案B的结构化对比表。
**评审反应：** "AI自动出对比报告？"

## 五、用户画像

### 核心人群
**独立开发者 / 技术创业者**
- 年龄：22-35岁
- 角色：全栈开发者、独立开发者、AI原型设计师
- 行为：每天使用至少2个AI工具写代码
- 痛点：在多个AI工具间切换、粘贴上下文、人工协调多个Agent

### 产品设计围绕"一个人需要团队协作效果"
- 核心场景：一个人 → 群聊 → 说需求 → 多个Agent讨论 → 产出最终结果
- 产品不要求用户有团队。Agent就是你的团队

## 六、竞品差异分析

| 产品 | 交互范式 | Agent间互动 |
|------|---------|------------|
| Cursor | 编辑器内嵌聊天 | 无 |
| Claude Code | CLI终端聊天 | 无 |
| JetBrains Air | IDE + Agent面板 | 并行但不交互 |
| The Cog | 无限画布编排 | DAG视觉编排 |
| Multica | 看板式管理 | Kanban任务分派 |
| **AgentHub** | **IM群聊** | **辩论·反驳·回应·裁决** |

**核心差异：** AgentHub 不仅让多个Agent"同时工作"，还让Agent之间可以"互相讨论"。这是现有产品都没有的。

## 七、技术架构

```
Frontend (Next.js + Tailwind + Inter)
  ├── Chat UI (对话列表 / 消息流 / 输入框)
  ├── Branch Manager (对话分支管理)
  ├── Card Renderer (代码块 / Diff / 预览 / PR / 部署)
  ├── Image Upload (截图→代码入口)
  └── Preview Panel (右侧4个Tab面板)

Backend (Next.js API Routes)
  ├── SSE Stream (流式消息 + 轮询降级)
  ├── Agent Proxy (LLM API调用)
  ├── Agent Registry (自建Agent管理)
  ├── Vision Proxy (图片→代码)
  ├── Task Runner (Agent主动找人 / 定时检查)
  └── Version Manager (版本快照)

Storage
  ├── IndexedDB (对话历史 + 分支 + Agent配置 + 版本快照)
  └── Vercel (部署)

Deployment: Vercel (需配置 maxDuration: 60)
```

### SSE + 轮询降级
Vercel Serverless Function 10s超时的解决方案：
1. 优先尝试SSE长连接
2. 超时后客户端通过taskId轮询获取结果
3. 生产环境可替换为WebSocket

## 八、前端设计系统

### 配色
```
页面背景:   #f0f2f5
应用表面:   #ffffff
侧栏背景:   #f7f8fa
强调色:     #1e6fff (飞书蓝)
成功:       #00c853
警告:       #ff9800
危险:       #f44336
静默审查:   #ef4444 (红色)
```

### 字体
- 正文/UI: Inter（字节核心产品使用的字体，评审感到熟悉）
- 代码: JetBrains Mono
- 无花哨装饰字体 — 字节审美是信息效率优先

### 圆角体系
```
xs: 4px (按钮) → sm: 6px → md: 10px (卡片) → lg: 16px (气泡) → xl: 20px (应用容器)
```

### 设计哲学
- 无纹理、无装饰、纯信息驱动
- 一个页面只有一个强调色
- hover才显示的操作按钮（保持界面干净）
- 滚动条只在hover时显示
